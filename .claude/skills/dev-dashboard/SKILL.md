# Developer dashboard

The dashboard is a React SPA in `web/dev` (TanStack Router + Query, `cmdk`) served at `/dev`
and embedded in the binary; its JSON API is `internal/modules/dev`, mounted at `/dev/api` behind
`dev.enabled → auth → tenant.exempt → can:dev.view`.

## Backend (`internal/modules/dev`)

- **Handlers call services, never repositories.** Services live in `services.go`
  (`SessionService`, `DeveloperService`, `FileBrowser`, `TelemetryService`, `TargetService`,
  `Auditor`) and next to their panel (`InspectorService` in `inspector.go`, `CommandService` in
  `commands.go`, `TenantService` in `tenants_panel.go`). Read-only panels may embed their
  repository; anything with rules or an audit record gets a method.
- **Mutations** declare `dev.manage` on the route: `r.With(h.manage).Post(...)` in `routes.go`.
  Read the actor with `authn.UserID(r)`.
- **Audit every mutation**: `h.audit.Record(ctx, actorID, "area.verb", target, params, started, err)`
  (detached context; IP and browser come from the request context). Give the new action key a
  readable label in `web/dev/src/routes/_app.actions.tsx` (`labels`).
- New dependencies go into `dev.Deps` (`base.go`) and are set in `internal/app/wiring.go`.
- Every endpoint must be in `api/openapi.yaml` (tag `Dev`, schemas named `Dev*`), then
  `make openapi`, `make openapi-check`, `cd web/dev && npm run openapi:gen`, and export a type
  alias in `web/dev/src/api/types.ts`.

## Adding a command to the Commands panel

Append to `devCommands` in `internal/app/dev_commands.go`:

```go
{
    Name: "cache:clear", Label: "Clear cache", Group: "Maintenance",
    Confirm:    true,  // changes data: ask first
    Background: false, // true for slow work: returns 202, the UI polls the run
    Description: "Empty the application cache.",
    Options: []dev.CommandOption{
        {Name: "dry_run", Label: "Dry run", Type: "bool", Default: "true"}, // bool|number|text|select
    },
    Run: func(ctx context.Context, options map[string]string, out io.Writer) error {
        fmt.Fprintln(out, "...") // shown in the run's terminal output
        return nil               // an error marks the run failed
    },
},
```

Reuse platform services (do not shell out). Runs are stored in `dev_actions` (`command.run`) with
their output, and appear in Ctrl+K automatically. Keep the CLI command (`internal/cli`, see the
`add-cli-command` skill) and the dashboard command doing the same work, under the same name.

## Frontend (`web/dev/src`)

- A page is `routes/_app.<name>.tsx` with `createFileRoute('/_app/<name>')`; the route tree is
  generated by the Vite plugin (`routeTree.gen.ts`, do not edit). Deep links use
  `validateSearch` (see `_app.actions.tsx`, `_app.inspector.tsx`, `?state=` on queue).
- **New page checklist:** one entry in `components/navigation.ts` (`group`, `icon`, a unique `g`
  shortcut `key`, `keywords`, `localOnly`); the sidebar, palette, shortcuts sheet and top bar read
  it. Then the page template: `PageHeader` (`title`, one-line `description`, `actions`, `meta`)
  → optional `.filters` row → content in `Card`s. New shared components go on `/dev/kit`
  (`routes/_app.kit.tsx`).
- UI kit: `components/ui.tsx` — layout `Stack`, `Cluster`, `Split`, `Grid`; `Card` (with `title`,
  `description`, `actions`, `flush` for a table or list), `CardHeader` (a sub-section), `StatTile`
  (tone colours only the value; `to` links it), `Badge` (`neutral|accent|ok|warn|danger|info|violet`),
  `StatusDot`, `LiveDot` (only for work running now), `DetailStrip`, `BackLink`, `Button`,
  `Drawer` (`size` md/lg/fit), `Modal`, `ConfirmDialog`, `Tabs`, `EmptyState`, `LoadingBlock`,
  `ErrorBox` (`onRetry`), `JsonView`, `CodeBlock`, `CopyButton`, `Kbd`, `Icon`; job pieces in
  `components/Jobs.tsx`; form controls in `components/inputs.tsx` (`Select`, `DatePicker`,
  `TimePicker`); charts in `components/charts.tsx` (Recharts: `DonutChart`, `HBarChart`,
  `TimeBars`, coloured by `Tone` classes on the tokens, `--series-1…6` for categories; a panel's
  chart data comes from a `/dev/api/<panel>/stats` endpoint that fills empty buckets). Never a native `<select>` or `type="date"` input. Status tones
  come from `format.ts` (`statusTone`, `stateTone`, `levelTone`, `sourceTone`).
- **Colour means something.** Green is healthy, red failed, amber needs a look; the accent marks
  what is selected or on (switches, active tabs and rows). A healthy screen looks grey.
- Data: `api<T>(path, {query, method, body, unwrap})` from `api/client.ts` with TanStack Query;
  invalidate related keys after mutations; show results with `useToast().push`. Every mutation
  confirms first (`ConfirmDialog`) when it changes or deletes data.
- Styles: `styles/tokens.css` (themes, accent presets, density, type scale), `base.css`,
  `components.css`, and one `styles/screens/<name>.css` per page that needs its own rules,
  imported from `styles.css`. Use tokens only (`--surface-*`, `--text-1..3`, `--border`,
  `--accent`, `--ok|warn|danger|info-fg/-subtle/-border`, `--fs-*`); no raw colours, no
  `font-size` outside the six `--fs-*` steps, no uppercase except table headers and nav sections,
  no idle animation. No inline `style={{…}}` for layout (data-driven widths and virtual-row
  offsets only). `npm run check:style` enforces the token rules and WCAG AA contrast.
- Keyboard: global shortcuts live in `components/shortcuts.ts` (they skip typing targets);
  overlays close on Escape through `useEscape` in `ui.tsx` (the top one only).

## Verify

`npx tsc --noEmit`, `npm run check:style` and `npm run build` in `web/dev`; Go gates from `verify-changes`; open the page
at `http://localhost:8080/dev/<page>` (with `make dev`) and click through it. Drag-and-drop cannot
be driven with synthetic mouse drags — dispatch `DragEvent`s with a `DataTransfer` in the browser
console instead.
