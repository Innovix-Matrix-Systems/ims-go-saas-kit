## Anatomy of a module

Small and medium modules are **flat**: one package, a handful of files, each with one job.

| File | Holds | Must not |
| --- | --- | --- |
| `routes.go` | paths → handlers, each with its permission | contain logic |
| `handler.go` | bind, call the service, respond | contain SQL or business rules |
| `request.go` | request and response DTOs, `NewXResponse` mappers | contain logic |
| `service.go` | business rules, tenancy, transactions, activity | import `httpx` or `authn` |
| `repository.go` | `Repository` interface + sqlc implementation | import `httpx` or `authn` |
| `model.go` | domain structs and row mappers | let `dbgen` types leak out |

Big modules (billing) keep `routes/handler/request` at the root, shared types in `domain/` and
business services in `service/`, which keeps the packages free of import cycles.

**Reference modules** to copy from: `branches` (small), `identity` (rich), `billing` (big).

## Generated code

These files are generated and **committed**. CI regenerates them and fails on any diff.

| File or folder | Generated from | Regenerate with |
| --- | --- | --- |
| `internal/dbgen` | `migrations/` + `sql/queries/` | `make sqlc` |
| `internal/contract` | `api/openapi.yaml` | `make openapi` |
| `web/app/src/api/schema.d.ts`, `web/dev/src/api/schema.d.ts` | `api/openapi.yaml` | `npm --prefix web/app run openapi:gen` (and `web/dev`) |
| `web/app/src/routeTree.gen.ts` | the files in `web/app/src/routes/` | the app's dev server or build |
| `docs/reference/*` | the CLI, `.env.example`, the permission catalog, the Makefile | `make docs-gen` |

`make gen-check` checks the Go and docs ones; the `web` and `app` CI jobs check the TypeScript ones.

<Aside type="tip" title="Building your own product on it?">
  Start with GitHub's **[Use this template](https://github.com/Innovix-Matrix-Systems/ims-go-saas-kit/generate)** button rather than a fork: you get a repository of
  your own with a clean history. Then run `make rename MODULE=github.com/you/your-app` to give it
  your module path, binary and names (see the [quick start](./quick-start.mdx)), and keep `docs/`:
  it documents your codebase. All of it is in [Make it yours](./make-it-yours.md).
</Aside>

## Where does X go?

| I want to… | Put it in |
| --- | --- |
| add a resource with CRUD | `ims gen module`, then `internal/modules/<name>` — see the [tutorial](../tutorial/first-module.mdx) |
| add an endpoint to a module | `request.go` → `service.go` → `handler.go` → `routes.go` ([recipe](../guides/modules.md#add-an-endpoint-to-an-existing-module)) |
| add a permission | `internal/authz/catalog.go`, then `ims permission:sync` |
| add a config setting | `internal/config/<section>.go` and `.env.example` |
| add a recurring task | `internal/app/schedule.go` |
| add a queue job | the module's `RegisterJobs`, registered in `platform.go` |
| add a screen to the app | a file in `web/app/src/routes/`, an entry in `navigation.ts`, a catalog folder in `i18n/catalogs/` ([Adding a screen](../app/adding-a-screen.md)) |
| change the app's colours or language | `web/app/src/styles/tokens.css`, `web/app/src/i18n/` ([Translations and theming](../app/translations-and-theming.md)) |
| add a CLI command | `internal/cli` |
| add a dashboard command | `internal/app/dev_commands.go` |
| change the schema | a new file in `migrations/` ([database guide](../guides/database.md)) |
