## Why this starter

<CardGrid stagger>
  <Card title="Laravel's batteries and workflow" icon="laptop">
    Thin handlers (`h.Bind`, `h.Data`), permissions on routes (`r.With(h.can("product.create"))`),
    services, one config file per section, artisan-style `ims` commands, and `ims gen module`
    scaffolds the stack. [What carries over](/getting-started/coming-from-laravel/).
  </Card>
  <Card title="Go's runtime, without the magic" icon="seti:go">
    One process that stays running, SQL typed by sqlc instead of an ORM, every dependency wired in
    plain code instead of a container, and tenant filters you can read instead of global scopes.
  </Card>
  <Card title="Multi-tenant, safe by default" icon="approve-check">
    Tenant and branch isolation in SQL that fails closed, RBAC, staff acting as a tenant or as a
    user (every request audited), per-tenant plan limits, and a test that fails any route without a
    permission.
  </Card>
  <Card title="Everything an API needs" icon="puzzle">
    Auth with OTP, two-factor (app or e-mail), invitations, sessions users can revoke, recovery and
    Google/GitHub sign-in · billing with plan limits · settings · feature flags with rollout ·
    activity log with a system audit log · public tenant routes · MCP server for AI agents (as a
    connector) · mail, SMS and push from one delivery system · notifications with preferences ·
    outbound webhooks · duplicate-write protection · files on local/S3/R2/MinIO · import/export ·
    backups · queue · scheduler · maintenance mode (`ims down` / `ims up`) · OpenTelemetry tracing ·
    RFC 9457 errors · OpenAPI.
  </Card>
  <Card title="A dashboard you'll actually use" icon="seti:html">
    Requests, logs, exceptions, queue, a delivery log with template previews, one-click commands, a
    maintenance-mode toggle, an inspector for health, routes, roles and config, tenants, settings,
    flags, files, sessions and an audit log. Status first, light or dark with your accent colour, and
    a keyboard for everything: Ctrl+K, `g` + a letter, `?`.
  </Card>
  <Card title="Fast feedback" icon="rocket">
    Type-safe SQL (sqlc), integration tests in a few lines (`testkit`), hot reload, and AI-agent
    skills that know the codebase.
  </Card>
  <Card title="One binary in production" icon="rocket">
    No containers needed: systemd runs the API, the worker and the scheduler from the same
    binary. Prefer Docker? One image and a `compose.yaml` run the same stack.
  </Card>
</CardGrid>
